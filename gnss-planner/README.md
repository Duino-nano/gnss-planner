# GNSS FIELD — ローカル衛星配置プランナー

Windows PCで起動し、緯度・経度または端末の位置情報を基準に、衛星の天空図と参考DOPを確認するWebアプリです。現在時刻と前後24時間に対応します。

## 起動

1. `Start.cmd` をダブルクリックします。
2. ブラウザで <http://localhost:3000> を開きます。
3. 「現在地を取得」、または緯度・経度を入力して「この地点を適用」を押します。
4. 「日時指定」や時間スライダー、グラフで時刻を切り替えます。「現在」で現在時刻に戻ります。

起動したウィンドウを開いたまま使用します。終了は `Ctrl+C`。すでに起動中ならURLを開くだけで利用できます。

必要環境はNode.js 22以降と現在のChrome・Edge・Safari等。npmによるインストールは不要です。起動スクリプトはPATH上のNode.js、またはこのPCのCodex付属Node.jsを探します。見つからない場合は https://nodejs.org/ のLTSを導入してください。

コマンドで起動する場合：

```powershell
node server.mjs
```

初回の軌道データ取得はインターネット接続が必要です。`data/gnss.json`に保存したデータはオフラインでも使えますが、衛星ごとの基準時刻から3日を超える計算は行いません。外部サイトのJavaScript・画像・フォントには依存しません。

## スマートフォンで使う

画面はスマートフォン幅に対応しています。実機のGPS取得には次の準備が必要です。

1. PCとスマートフォンを同じWi-Fiへ接続します。
2. 初回のみ、このフォルダーで `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-https.ps1` を実行します。プロジェクト内にローカルCAとサーバー証明書を生成します。Windowsの信頼ストアやファイアウォールは変更しません。実行済みなら `certs/addresses.txt` のIPを確認してください。
3. **`certs/local-ca.cer` だけ**をスマートフォンへコピーし、端末の設定でCA証明書としてインストール・信頼します。iPhoneはプロファイルのインストール後、「一般 → 情報 → 証明書信頼設定」で明示的な信頼が必要です。Androidは機種ごとの証明書インストール画面を利用します。業務端末でインストールが制限されている場合はPCで利用してください。
4. `Start-LAN-HTTPS.cmd` を起動します。
5. 起動時に表示される `https://PCのIPアドレス:3443` をスマートフォンで開きます。現在地ボタンは**開いているスマートフォン自身**の位置情報を取得します。

ネットワーク接続がブロックされる場合は、WindowsファイアウォールでNode.jsの受信をプライベートネットワークに限定して許可する必要があります。Wi-Fiの端末間通信制限も確認してください。HTTPS証明書を信頼する前の警告画面を迂回する運用は避け、信頼設定を完了させてください。

`local.pfx` と `password.txt` は秘密鍵情報なので共有しないでください。`certs/` はGitの管理対象外ですが、親フォルダーがOneDriveなので同期対象になる可能性があります。証明書はこのツール専用です。CAの秘密鍵は保存せず、サーバー証明書の有効期限は90日です。PCのIPが変わった場合や期限更新時は、既存の `certs` フォルダーを別名へ移して再生成し、端末側の旧CAを削除して新CAを信頼してください。

位置の手入力だけなら `node server.mjs --lan` によるHTTPでも使えます。この場合、スマートフォンの現在地取得はブラウザの制約で利用できません。

## 表示・計算の前提

- 天空図と衛星一覧は初期状態で「計算候補だけを表示」です。選択された系統のうち最低仰角以上で軌道データが有効な衛星だけを表示します。チェックを外すと最低仰角未満も確認できます。この表示切替自体でDOPの計算対象は変わりません。
- 使用受信機はユーザー提供画像より **mosaic-go G5 P3H**。メーカー公式仕様で本アプリの5系統への対応を確認しました。補正元・実際の使用衛星は未確認です。「計算候補」は受信機でのRTK使用を確認した意味ではありません。機種・補正サービスの対応確認と、実際に使用している衛星だけの表示は別途受信機データが必要です。

- GPS、QZSS、Galileo、GLONASS、BeiDouの5系統。初期地点は東京駅付近であり、ユーザーの現在地ではありません。
- 緯度・経度はWGS84、任意入力の高さは楕円体高（m）。未指定は0 m。GPS以外の位置情報源が使われることもあります。
- 北を上、東を右とした地平座標の天空図。中央90°、外周0°。点の位置は真の方位・仰角です。表示が密な場所のラベルは省略し、点または一覧のボタンで詳細を確認できます。
- 5秒間隔で現在の配置を更新。軌道配布元へのアクセスは6時間間隔、失敗時の再試行は15分間隔です。
- 時間グラフは現在の前後24時間を15分ごとに計算（193時点）。PDOPとDOP対象数を左右の別軸に表示します。日時操作は日本時間（JST）。内部はUTCです。
- DOPは各衛星の等重み、局所ENUの位置3成分＋選択した衛星システムごとの独立時計差を使う保守的なモデルです。QZSSとGPSも別時計差です。QR分解で共分散を計算し、衛星数不足やランク不足を検出します。PDOP²=HDOP²+VDOP²です。
- 最低仰角は初期15°、画面では0〜60°。最低仰角未満は淡色で表示し、DOPには含めません。
- 地平線上の候補数であり、受信機が実際に捕捉・使用している衛星数ではありません。衛星の運用状態・信号の対応・RTK FIX/FLOATは取得していません。試験機や非運用機を含む可能性があるためDOPは参考値です。
- 衛星番号は配布元の表記を使用します。GPSはPRN、QZSSは放送PRN、BeiDouはC番号。GalileoはGSAT機体名、GLONASSはNORAD番号で、PRNに見せかけた番号変換をしません。
- 建物・樹木・山の遮蔽、マルチパス、大気、アンテナ、補正情報、受信機の処理はモデル化していません。cm単位の精度やRTK FIX可否を予測するツールではありません。

## 軌道データと当初要件との差分

初期検証ではBKG配布元への接続を確立できなかったため、初版はCelesTrakのGNSSグループのGP/OMMデータを使用します。軌道計算はSGP4/SDP4です。

**当初案のRINEX航法暦・過去アーカイブ・アルマナックの切り替えは未実装です。** 前後24時間とも取得済み軌道からの伝播計算で、過去表示は当時の運用状態や当時取得できたデータを再現しません。最新データを無期限に使わず、各軌道基準時刻から3日以内という表示用の上限を設定しています。2日超は古いデータとして警告します。上限は本ツールの設計上の制限であり、精度の保証ではありません。軌道変更・衛星停止などは予測できません。

RTK作業判断をより厳密にする次段階では、RINEX/アルマナック、衛星health・対応信号、外部受信機の実測を追加する必要があります。

## プライバシーとローカル接続

初期設定はPC内（127.0.0.1）からのみ接続できます。`--lan`を明示するとLANからアクセス可能になります。位置はブラウザからローカル計算サーバーへ送信し、CelesTrakへは送信しません。住所取得では緯度・経度を国土地理院へ、接続失敗時はHeartRails Geo APIへ送信します。地図を開くと表示範囲に応じたタイルを国土地理院へ要求します。サーバーは地点や閲覧履歴をログ保存しません。住所結果はプロセス内に最大256地点キャッシュします。ブラウザ・OSの現在地サービス自体が位置推定にネットワークを使う場合があります。

## 自動現在地・住所・地図

起動時にブラウザの位置情報取得を自動で開始します。初回は位置情報の許可が必要です。GPS搭載の有無はブラウザから判別できず、PCではWi-Fiなどによる位置になる場合があります。取得精度を表示し、取得失敗時は初期地点であることを明示します。移動中の追従はチェックボックスで有効にできます。スマートフォンのLAN接続では信頼されたHTTPSが必要です。

「地図から場所を選ぶ」を開き、地図上をクリック／タップすると評価地点と衛星計算が切り替わります。地図を移動して「地図の中心を使用」でも選べます。地図選択・座標入力後は端末位置の追従を停止し、遅れて届いた位置情報で上書きしません。地図選択時の高さは0 mと仮定します。

住所は日本国内の町丁目程度の参考表示です。国土地理院への接続失敗時はHeartRailsの近隣住所候補を使用し、「付近」と代表点までの距離を明示します（5 km超の候補は表示しません）。番地や現地住所の保証ではありません。住所・地図はインターネット接続が必要で、取得できなくても座標での評価は利用できます。

地図ライブラリはLeaflet 1.9.4（同梱、ライセンスは `vendor/leaflet-LICENSE`）。地図は[地理院タイル](https://maps.gsi.go.jp/development/ichiran.html)。住所候補は[HeartRails Geo API](https://geoapi.heartrails.com/)、「[位置参照情報ダウンロードサービス](https://nlftp.mlit.go.jp/isj/)」（国土交通省）を加工して作成。

## 検証

```powershell
node --test test/*.test.mjs
node scripts/verify-live.mjs
```

前者はネットワーク不要の単体テストです。後者は起動中のlocalhost:3000に接続し、現在/±24時間、5系統、マスク、データ検証、グラフ、入力エラー、サーバーの公開ファイル制限を検査します。

GPSアルマナックとの独立比較は `node scripts/compare-gps.mjs` で実行できます。CelesTrakの公開アルマナックとGPを比較し、方位・仰角差を報告します。比較値は実際の電波観測の誤差ではありません。

## 衛星配置による測位への影響
画面上部に候補数・仰角帯（30°未満、30〜60°未満、60°以上）・8方位別の数・方位の最大空白幅を表示します。対象はDOP候補のみです。全衛星表示に切り替えても評価対象は変わりません。
PDOP表示区分は本アプリ独自の目安（2未満／2以上5未満／5以上）で、メーカーのFIX基準や車両の走行合否基準ではありません。DOP欠損は評価不能です。低仰角への偏り・方位の空白・未知数に対する衛星数の余裕・軌道データの欠損を補足表示します。天頂付近の方位分布は参考にとどめ、総合的な配置はDOPで比較してください。
最低仰角を15°から30°へ上げて低い空が使えない場合を比較できます。実際の障害物形状や受信品質は反映しません。DOPの根拠：https://gssc.esa.int/navipedia/index.php?title=Positioning_Error

## はじめて使う場合
「場所を選ぶ → 時間を選ぶ → 結果を読む」の案内から各操作に移動できます。上部に「有利な並び方」「位置のずれに注意」「ずれが大きくなりやすい」「判断できない」の説明を表示します。評価区分・計算式は従来と同じです。
DOP・衛星の種類・各衛星の一覧・任意の高さ入力は折りたたみ表示です。「30°以上で比較」で低い空の衛星を外し、「15°に戻す」で標準の角度に戻せます。これらは空の見え方を仮定した比較で、現地の障害物を検出する機能ではありません。

## 時間帯の細かな比較
時間グラフはPDOPの実数を結ぶ折れ線です。背景色は評価区分を示し、同じ有利な範囲でも細かな増減を保持します。縦軸は上が0、下ほどPDOPが大きくなる反転軸です。上ほど配置が良好です。表示する最大値はデータで調整します。今後24時間の15分刻みの最小・最大値と、その時刻へ移動するボタンを表示します。欠損は灰色の区間と線の切れ目で示します。

### 現在地が取れない場合
地図上部に取得中・失敗理由・再取得ボタンを表示します。未取得の初期地点では住所検索を行わず、「現在地の住所は未取得」「東京駅付近のプレビュー」と表示します。Windowsやブラウザの位置情報設定を確認し、アプリ内ブラウザで取得できないときは通常のEdge/Chromeでも試してください。外付けRTK受信機の接続だけで、その位置がブラウザへ渡るわけではありません。本アプリは受信機と直接接続していません。

## 画面構成（2026-10-09改訂）
PCは左に場所・時間・計算条件、右に配置の評価・時間比較・天空図を配置。スマートフォンでは縦一列になります。評価の内訳、住所の出典、座標入力、比較の最小最大時刻、衛星一覧は折りたたみから確認できます。評価区分の「有利」は主画面では「良好」と表記しています（PDOPの境界・計算方法は変更なし）。
